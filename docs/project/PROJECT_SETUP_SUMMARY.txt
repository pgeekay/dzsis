KEY PRINCIPLES
================================================================================
1. Extension Layer: All California enhancements are "extension" tables, not
   modifications to OpenSIS core tables. This preserves upgrade path.

2. Incremental Development: 13 phases, each with testable deliverables.
   Tests and documentation updated with each phase.

3. Data Separation: OpenSIS core data separate from CA extension data,
   linked via foreign keys.

4. Validation First: Comprehensive validation before data save and before
   CALPADS extract generation.

5. Effective Dating: All California records support effective-dated history.

ARCHITECTURE SUMMARY
================================================================================

Extension Layer Pattern:
  OpenSIS Core Tables (unchanged)
            ↓
  California Extension Tables (ca_* prefix)
            ↓
  Validation Layer (validation rules + result storage)
            ↓
  CALPADS Extract Generator (SENR, SINF, SPRG, SELA, STAS)
            ↓
  CSV/API Export (for external systems)

California Extension Tables (by domain):
  Student:      ca_student_profile, ca_student_demographic_history,
                ca_student_language, ca_student_guardian_education
  Enrollment:   ca_student_enrollment, ca_enrollment_status_history,
                ca_enrollment_code_map, ca_school_year_calendar
  Programs:     ca_program, ca_student_program, ca_student_program_history
  Attendance:   ca_attendance_code_map, ca_daily_attendance_summary
  Discipline:   ca_discipline_incident, ca_discipline_student_incident,
                ca_discipline_action
  CALPADS:      ca_calpads_extract_batch, ca_calpads_extract_file,
                ca_calpads_validation_rule, ca_calpads_validation_result

Code Sets Framework:
  ca_code_set:       Defines code domains (GradeLevel, Gender, etc.)
  ca_code_value:     Valid values for each code domain
  ca_code_crosswalk: Maps OpenSIS values to California values
